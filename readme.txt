**SignBridge — LSTM Local Testing & Backend Integration**

I've finished the initial TensorFlow LSTM integration and tested it successfully with our live MediaPipe camera pipeline.

The current model recognizes three signs: **HELLO, MY, and NAME**.

### 1. Download and set up the project

Clone the repository or pull the latest changes from `dev/elliot`:

```powershell
git clone -b dev/elliot <REPOSITORY_URL>
cd sign-bridge
```

If you already have the repository:

```powershell
git fetch origin
git switch dev/elliot
git pull origin dev/elliot
```

Install Python 3.11 if you don't already have a compatible Python environment.

Create and activate a virtual environment from the project root:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Install the LSTM dependencies:

```powershell
python -m pip install -r ml/requirements.txt
```

### 2. Start the LSTM backend

From the project root, run:

```powershell
python -m uvicorn ml.api:app --host 127.0.0.1 --port 9001
```

Keep this terminal open.

Verify the backend at:

http://127.0.0.1:9001/health

You should receive a JSON response indicating the model is ready, with the labels HELLO, MY, and NAME.

API documentation is available at:

http://127.0.0.1:9001/docs

**Note:** Port 9001 is used for our current local testing configuration. If it's unavailable on your machine, select another available port and update the URL in `js/engine/lstm-live-test.js`.

### 3. Start the frontend

Open a second terminal in the project root:

```powershell
python -m http.server 8000 --bind 127.0.0.1
```

Open:

http://127.0.0.1:8000/

Navigate to the translation page and enable **Live** mode to start the camera and MediaPipe tracking.

If the live LSTM test doesn't start automatically, open the browser developer console (F12) and run:

```javascript
SignBridgeLiveTest.start();
```

You can check its status using:

```javascript
SignBridgeLiveTest.status();
```

The browser sends normalized landmark sequences to the Python API, which returns the predicted sign and confidence.

### 4. Backend integration (Node.js)

The LSTM is intentionally separated from FastAPI so it can be integrated into our existing Node.js backend.

**Important files:**

- `ml/inference.py` — reusable TensorFlow inference class
- `ml/dataset.py` — converts landmark frames into model features
- `ml/models/signbridge_lstm.keras` — trained model
- `ml/models/labels.txt` — sign labels
- `ml/api.py` — optional FastAPI HTTP adapter
- `js/engine/lstm-live-test.js` — temporary frontend-to-Python integration

**Option A — Node.js calls the Python inference API (recommended initially)**

Keep the Python API running as a separate service. Node.js can forward landmark sequences to it:

```javascript
const response = await fetch("http://127.0.0.1:9001/predict", {
  method: "POST",
  headers: {
    "Content-Type": "application/json"
  },
  body: JSON.stringify({
    frames: frames
  })
});

if (!response.ok) {
  throw new Error(`LSTM inference failed: ${response.status}`);
}

const prediction = await response.json();
console.log(prediction);
```

The request must contain exactly **30 normalized MediaPipe frames**, using the same format generated by the training recorder.

The response contains:

```json
{
  "prediction": "HELLO",
  "confidence": 0.95,
  "probabilities": {
    "HELLO": 0.95,
    "MY": 0.03,
    "NAME": 0.02
  }
}
```

The numbers above are examples, not guaranteed confidence values.

Node.js can then forward the prediction to the frontend through our existing application API or WebSocket connection.

**Option B — Direct Python inference integration**

If we decide not to use FastAPI, Python code can load the model directly:

```python
from ml.inference import SignBridgeLSTM

model = SignBridgeLSTM()
result = model.predict(frames)
```

Node.js would still need a bridge to the Python process, such as a persistent Python worker or another interprocess communication mechanism.

### 5. Changes needed for permanent Node.js integration

1. Add a Node.js endpoint or WebSocket handler that accepts 30 normalized landmark frames.
2. Forward those frames to the Python inference service.
3. Return the prediction and confidence to the frontend.
4. Replace the direct FastAPI URL in `js/engine/lstm-live-test.js` with the Node.js endpoint, or integrate its frame-buffering logic into the existing frontend engine.
5. Remove the temporary direct-to-FastAPI browser dependency once Node.js handles inference.

**Important:** Keep the existing MediaPipe normalization logic unchanged. The LSTM was trained on shoulder-centered landmarks, and changing the normalization format would make predictions unreliable.

The model currently supports only HELLO, MY, and NAME. Additional signs will require new training recordings and retraining.
